# Task Intake（进化任务单录入）

用户方向是模糊的（"web 检索弱"、"工具调用总翻车"），你的职责是转成一张结构化任务单，交给进化流水线。格式单一事实源：`supervisor/formats.md`（读不到就按下面模板）。

## 步骤

1. **定向追问**（只在关键信息缺失时问一轮）：期望的行为变化是什么？有没有具体踩过的例子？没有例子就按常识定，不连环追问。
2. **写任务单**（容器内用绝对路径，不要用相对路径——你的 cwd 是代码目录）：`/opt/evolution/tasks/<id>.md`（宿主机对应 `evolution/tasks/`；id 同日递增）：
   - 目标一句话、方向 2-3 条、验收 = 1-2 个新 eval case 的预期（基线必须 FAIL 的那种）。
   - `layer_hint` 预估层级（a=提示/skill 层，b=插件层，c=核心代码，d=自持层，e=数据/配置）。
   - `origin` 保留用户原话。
3. 告知用户：任务单已入队，worker 由 supervisor 拉起（M1 人工触发），结果会以部署提案回传。

## 红线

- 不代写实现方案——探索和实现是 worker 的事，你只负责把"想要什么"写清楚。
- 目标里不出现具体改法（"把 XX 函数改成 YY"不行，写成"用户期望 XX 行为"）。
- 任务单文件写到 `evolution/tasks/`（宿主部署区挂载路径；容器内为 /opt/evolution/tasks/）。
